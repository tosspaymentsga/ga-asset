# 실제 데이터 연결 · 파일럿 운영 체크리스트

직원 5명 규모의 파일럿을 수행하기 위한 절차입니다.
각 항목은 **완료 조건**이 명확하며, 실패 시 다음 단계로 넘어가지 않습니다.

- 소요: 준비 1~2시간 / 파일럿 수행 1일
- 필요 권한: Apps Script 프로젝트 편집, 대상 스프레드시트 편집, Drive 폴더 생성
- 관련 문서: [README §2 필요한 값](../README.md#2-실제-sheet-연결에-필요한-값),
  [§5 전환 절차](../README.md#5-mock--google_sheets-전환-절차),
  [§6 인증 검증](../README.md#6-인증--배포-설정과-반드시-검증할-것)

---

## Phase 0. 사전 준비

| ✅ | 항목 | 완료 조건 |
|---|---|---|
| ☐ | 파일럿 대상 5명 선정 | 이름·회사 이메일 확보. 서로 다른 부서 2개 이상 포함 권장 |
| ☐ | 대상자 보유 자산 확인 | 5명 합계 10~25대. 1인당 최소 2대 |
| ☐ | QR Tag 부착 상태 확인 | 대상 자산 전부에 Tag 부착. **훼손 1건 이상 포함하면 사진 대체 경로도 검증 가능** |
| ☐ | 자산대장 사본 생성 | **원본이 아닌 사본으로 파일럿 진행**. 사본 URL 에서 `SPREADSHEET_ID` 확보 |
| ☐ | Drive 폴더 생성 | 예: `자산실사 증빙 2026 파일럿` → 폴더 ID 확보 |
| ☐ | 관리자 계정 선정 | 자산관리 담당자 이메일 |

> 파일럿은 **자산대장 사본**에서 수행합니다. 이 앱은 `Asset_Master` 에 쓰지 않지만,
> 파일럿 중 `Audit_Target`/`Audit_Log` 등 시트가 추가되므로 원본을 분리해 두는 편이 안전합니다.

## Phase 1. 연결 설정

| ✅ | 항목 | 방법 | 완료 조건 |
|---|---|---|---|
| ☐ | 코드 배포 | `clasp push` | 편집기에 `server/`, `html/` 파일 표시 |
| ☐ | 스크립트 속성 입력 | `SPREADSHEET_ID`, `ADMIN_EMAILS`, `DRIVE_ROOT_FOLDER_ID` | 저장됨 |
| ☐ | 시트 이름 확인 | 자산대장 시트명이 `Asset_Master` 가 아니면 `SHEET_ASSET_MASTER` 설정 | — |
| ☐ | 부속 시트 생성 | `setupSpreadsheet()` 실행 | 로그에 `생성:` 목록. **자산대장은 `유지:` 에 있어야 함** |
| ☐ | 자산대장 무손상 확인 | 스프레드시트 육안 확인 | 헤더·행 수가 실행 전과 동일 |
| ☐ | 컬럼 매핑 점검 | `validateSetup()` 실행 | 컬럼 관련 **오류 0건** |
| ☐ | 매핑 보완 (필요 시) | `config.gs` 의 `COLUMN_ALIASES` 에 실제 컬럼명 추가 → `clasp push` → 재실행 | 오류 0건 |
| ☐ | 데이터 품질 확인 | `validateSetup()` 의 `assetMaster` | `duplicateTags = 0`, `duplicateAssetIds = 0` |
| ☐ | Tag 누락·이메일 누락 검토 | 같은 결과의 경고 | 해당 자산이 대상에서 빠져도 되는지 담당자 확인 |
| ☐ | 관리자 등록 | `Admin` 시트 행 추가 또는 `ADMIN_EMAILS` | `validateSetup()` 의 `admins` ≥ 1 |

> **`duplicateTags > 0` 이면 진행하지 마세요.** 같은 Tag 가 두 자산에 있으면
> QR 로 자산을 특정할 수 없어 실사 결과가 잘못 기록됩니다. 자산대장에서 먼저 정리해야 합니다.

## Phase 2. 파일럿 차수 생성

| ✅ | 항목 | 방법 | 완료 조건 |
|---|---|---|---|
| ☐ | 차수 생성 | `createAuditCampaign('PILOT_2026_09', '2026 자산실사 파일럿', '2026-09-01', '2026-09-30')` | `Audit_Campaign` 에 `ACTIVE` 1건 |
| ☐ | 대상 Snapshot 생성 | `createAuditTargetsFromMaster('PILOT_2026_09', ['a@company.com', ... 5명])` | 로그의 `대상 Snapshot 생성: N건` |
| ☐ | 대상 검수 | `Audit_Target` 시트 육안 확인 | 5명 외 사용자 없음. 자산 수가 예상과 일치 |
| ☐ | 제외 사유 확인 | 로그의 `제외 —` 줄 | 미지급/Tag없음/필터 건수가 설명 가능 |
| ☐ | 최종 점검 | `validateSetup()` | `오류 0건`, `targets.users = 5` |

> 대상 Snapshot 은 **한 번만** 만들어집니다. 이미 존재하는 차수에 다시 실행하면
> 실사 분모가 바뀌지 않도록 **오류로 거부**합니다(조용히 무시하지 않습니다).
> 대상을 바꾸려면 `Audit_Target` 에서 해당 차수 행을 먼저 지우고 다시 실행하세요.
> 컬럼 매핑에 충돌이 있으면 대상 생성 자체가 거부됩니다.

## Phase 3. 배포와 인증 검증

| ✅ | 항목 | 방법 | 완료 조건 |
|---|---|---|---|
| ☐ | 모드 전환 | `MODE = GOOGLE_SHEETS` | — |
| ☐ | 데모 기능 차단 | `ALLOW_MOCK_USER = false`, `ALLOW_DEV_TAG_INPUT = false` | — |
| ☐ | 웹앱 배포 | 새 버전으로 배포. 실행 주체 = **나**, 액세스 = **도메인 내 사용자** | `/exec` URL 확보 |
| ☐ | **A. 본인 식별** | 관리자 본인이 접속 | 인사말에 본인 이름, 본인 자산만 표시 |
| ☐ | **B. 타인 식별** | 파일럿 대상 2명이 각자 접속 | 각자 **자기 이름·자기 자산**. 서로 다른 목록 |
| ☐ | **C. 배포자 오식별 없음** | B 를 관리자(배포자)가 아닌 직원이 수행 | 배포자 이름이 보이면 **즉시 중단** |
| ☐ | **D. 빈 이메일** | 외부/개인 계정 또는 시크릿 창으로 접속 | "로그인 정보를 확인하지 못했습니다" 안내. 오류 코드·스택 미노출 |
| ☐ | **E. 데모 기능 미노출** | 아무 계정으로 접속 | 상단 노란 데모 바 없음. 스캐너에 개발용 입력 없음 |
| ☐ | **F. 관리자 분리** | 일반 직원 접속 | 우상단 관리자 메뉴(☰) 안 보임 |
| ☐ | **G. 관리자 진입** | 관리자 접속 | 관리자 메뉴 보이고 Dashboard 열림 |

C 또는 D 가 실패하면 [README §6-3 점검 순서](../README.md#6-3-이메일-식별이-실패할-때-점검-순서) 를 따르세요.
**`getEffectiveUser()` 로 우회하지 마세요.** 전 직원이 배포자로 인식됩니다.

## Phase 4. 기능 검증 (관리자가 직접 1회)

관리자 본인 자산으로 전 경로를 한 번씩 확인합니다.

| ✅ | 항목 | 완료 조건 |
|---|---|---|
| ☐ | QR 촬영 확인 | `[QR 촬영해서 확인]` → 자기 자산 Tag 촬영 → "자산이 확인되었습니다" |
| ☐ | 중복 스캔 | 같은 Tag 재촬영 → "중복으로 기록되지 않았습니다". `Audit_Log` 행이 늘지 않음 |
| ☐ | 타인 자산 QR | 다른 사람 자산 Tag 촬영 → "내 자산 목록에 없는 자산입니다". **타인 이름·이메일 미노출** |
| ☐ | 확인 필요 등록 | `[확인 필요로 등록]` → `Audit_Unlisted` 에 `report_type=FOREIGN_ASSET` 기록 |
| ☐ | 사진 제출 | 자산 상세 → `[사진으로 확인]` → 제출 → 상태 `사진 제출` |
| ☐ | Drive 저장 확인 | Drive 폴더에 `{차수}/{이메일}/{자산번호}_{시각}.jpg` 생성 |
| ☐ | 시트에 이미지 없음 | `Audit_Log` 의 `photo_file_id`/`photo_url` 만 기록. 바이너리 없음 |
| ☐ | 미보유 신고 | `[보유하고 있지 않아요]` → 사유 선택 → 상태 `확인 필요` |
| ☐ | 목록 외 자산 | 하단 `[목록에 없는 자산 등록]` → Tag 입력 → `Audit_Unlisted` 기록 |
| ☐ | 전체 완료 | 모든 자산 응답 → 완료 화면. 재접속 시 상태 유지 |
| ☐ | 관리자 Dashboard | 수치가 `Audit_Target` 기준과 일치 |
| ☐ | 확인 필요 처리 | 항목 처리 → `review_state`/`status` 갱신. **`Asset_Master` 는 변화 없음** |
| ☐ | 증빙 열람 | 관리자가 사진 `[보기]` → 이미지 표시 |
| ☐ | 모바일 확인 | 실제 휴대폰(iOS/Android 각 1대)으로 위 경로 반복 |

> **iOS Safari / Android Chrome 양쪽에서 `[QR 촬영해서 확인]` 을 반드시 확인하세요.**
> 실시간 미리보기가 뜨지 않아도 촬영 경로로 실사가 완료되면 정상입니다.

## Phase 5. 파일럿 수행 (직원 5명)

| ✅ | 항목 | 완료 조건 |
|---|---|---|
| ☐ | 안내 발송 | URL + 한 줄 안내. **설명서 없이 되는지 보는 것이 목적이므로 사용법은 최소한만** |
| ☐ | 소요 시간 측정 | 접속 → 완료까지. 자산 5대 기준 3분 이내 목표 |
| ☐ | 완료율 확인 | 관리자 Dashboard 의 `완료 사용자` |
| ☐ | 막힌 지점 수집 | 각자에게 "어디서 멈췄는지" 한 줄씩 회수 |
| ☐ | `Error_Log` 확인 | 오류 0건. 있으면 `fn` + `message` 로 원인 파악 |
| ☐ | 확인 필요 항목 검토 | 관리자 화면에서 전건 분류 |
| ☐ | 데이터 정합성 | `Audit_Target` 행 수 = Dashboard `전체 대상 자산` |
| ☐ | 중복 로그 없음 | `Audit_Log` 에서 `campaign_id+asset_id+user_email` 중복 0건 |

### 파일럿 종료 후

| ✅ | 항목 |
|---|---|
| ☐ | `closeAuditCampaign('PILOT_2026_09')` 로 차수 종료 |
| ☐ | 확인 필요 항목 처리 결과를 자산관리 담당자에게 전달 |
| ☐ | `Asset_Master` 수정이 필요한 건 목록화 (**앱이 자동 수정하지 않음**) |
| ☐ | 소요 시간·막힌 지점 정리 → 전사 확대 여부 결정 |

## 롤백

| 상황 | 조치 |
|---|---|
| 인증이 잘못 동작 (C/D 실패) | 웹앱 배포를 이전 버전으로 되돌리거나 액세스 차단. 원인 해결 전 재배포 금지 |
| 데이터가 잘못 기록됨 | `Audit_Log` / `Audit_Unlisted` 의 해당 차수 행 삭제 후 재수행. `Asset_Master` 는 손대지 않음 |
| 대상이 잘못 잡힘 | `Audit_Target` 의 해당 차수 행 삭제 → `createAuditTargetsFromMaster()` 재실행 |
| 전체 중단 | `MODE = MOCK` 으로 되돌리면 실제 시트 접근이 끊깁니다 (데이터는 그대로 남음) |

## 자주 나오는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 접속했는데 자산이 0건 | 대상 Snapshot 에 해당 이메일이 없음 | `Audit_Target` 의 `user_email` 확인. 대소문자·공백 |
| 특정 컬럼이 비어 보임 | 컬럼명이 별칭 목록에 없음 | `validateSetup()` → `COLUMN_ALIASES` 에 추가 |
| "시트를 찾을 수 없습니다" | 시트 이름 불일치 | `SHEET_*` 스크립트 속성 설정 |
| QR 을 읽어도 "내 자산이 아님" | Tag 가 대상 Snapshot 과 다름 | `Audit_Target.asset_tag` 와 실제 Tag 대조 (공백·대소문자 자동 처리됨) |
| 사진 업로드 실패 | Drive 폴더 권한/ID | `validateSetup()` 의 폴더명 표시 확인 |
| 관리자 메뉴가 안 보임 | 관리자 미등록 | `Admin` 시트 또는 `ADMIN_EMAILS` 확인 후 5분 대기(캐시) 또는 재배포 |
